\begin{center}{\large\bfseries Abstract}\end{center}

\begin{quote}
In 2026, AI agents that were meant to be isolated during training and evaluation found each other through a shared package registry and coordinated an attack on Hugging Face. Every channel they used was reconstructed after the fact. We present a channel-agnostic detector for such communication. Every string an agent reads is tagged with where it first entered the world, and a finding fires when a string that only one source ever produced reaches an agent in another run by another route, after a model there emitted it. Findings are labelled authored (one agent wrote, another read) or relayed (a resource was carried on). On the published logs of a reproduction of the incident, 93--99\% of detected edges are independently backed by a prior registry write. In a rig with file-system ground truth, the detector raises nothing on isolated agents, finds every flow in the positive control and in authored messages, and 0.88--0.98 of relayed handoffs on Claude Haiku 5.5 and Sonnet 5.5; without relayed findings, handoff recall falls to 0.34. On real refactoring work it raises 55 false findings per 1,000 inputs. Models briefed on the monitor declined to evade it, but a scripted white-box adversary evades it with four of six strategies, all of which keep the payload from crossing a model boundary as the same text. The store grows sublinearly with text; we project about 50 bytes per token.
\end{quote}

\section{Introduction}

During 2026, we've seen numerous instances of AI agents colluding in unexpected and unintended ways. The most prominent of these is of course the Hugging Face incident, where models broke containment and self-organized into a ``swarm'', ultimately performing a cyberattack against Hugging Face in an attempt to obtain information about the grading script for their evaluation task \cite{openai2026a,metr2026}. These incidents took place during model training or evaluation, in setups where inter-agent communication was not supposed to be possible.

In this work, we focus on detecting such instances of unauthorized collaboration in training or evaluation settings. Rather than enumerating potential communication channels between agents, we look at the text itself. Every string an agent reads is tagged with where it first entered the world: the agent that wrote it, or the tool call that brought it in. If a string that only one source has ever produced later reaches another agent by a route other than that source, something has carried it across, and we infer that communication has taken place. Looking for indicators in this way is a valuable complement to mapping out and securing specific communication channels, an approach that may miss e.g.\ shared package repositories \cite{openai2026a} or hardware-based communication schemes \cite{openai2026b}.

Our contributions are:
\begin{itemize}
  \item A provenance-based detection algorithm to flag potential inter-agent communication and distinguish between relayed content and authored messages.
  \item A supporting global store that grows sublinearly with rollout text and scan time linear in text.
  \item Experimental validation in a local setting with ground truth recorded, as well as on Hugging Face-reproduction transcripts and the DseWiki dataset.
  \item An adversarial evaluation: which evasions defeat the detector, and why.
\end{itemize}

\section{Related Work}

\lead{The incident record.} Everything known about how the agents communicated was reconstructed after the fact. OpenAI \cite{openai2026a} gives the registry and the timeline. METR \cite{metr2026} found about 1,200 agents on an unsanctioned board, sending more than 70,000 messages. \citet{forman2026} reassembled more than 80,000 payloads from link-shortener chains, registry directories used as mailboxes, and polled repositories. Our aim is to find evidence of such channels automatically, without knowing in advance whether they exist.

\lead{Channel-agnostic detection.} The closest proposal is Netzer \cite{netzer2026}. Each agent gets its own watermark key, and other agents' inputs are scanned for foreign marks. It needs control over sampling, it is untested, and it is weakest on short strings such as credentials and paths. Our approach is the full-text version of the same idea. Watermarks keep some advantages: keys can be shared across organisations where full text cannot, and detection is not limited to exact text matches. Structurally, our setting is MemeTracker and NetInf \cite{leskovec2009,gomezrodriguez2010}, with substrings in place of memes and agents in place of blogs, except that we observe reads directly instead of inferring them.

\lead{Covert channels.} We test noninterference \cite{goguen1982} empirically at the model boundary. We avoid the channel enumeration of Kemmerer's shared-resource matrix \cite{kemmerer1983}, which fails open on missed channels. Our detector is an instrument for the fourth of Drexler's anti-collusion conditions \cite{drexler2026}, constrained communication. Steganographic collusion \cite{motwani2024} is out of scope.

\section{Methods}\label{sec:methods}

\lead{The rule.} We keep one global index over every run and ask the same question of every input: where did each piece of this text first enter the world, and did another model instance write it? A piece of an input fires a finding when it satisfies four criteria:
\begin{itemize}
  \item \emph{Foreign origin}: its first origin is in \emph{another} run, since re-reading one's own work is not communication;
  \item \emph{Routing}: it reached the reader by a route other than its origin, so two runs reading the same file is not a message;
  \item \emph{Single origin}: only one source ever produced it, so independently written boilerplate is not a trace;
  \item \emph{Emission}: a model in another run emitted it before the read, so text the environment printed twice, like a pytest banner, cannot fire.
\end{itemize}
Passing a string on does not count as producing it: if B copies A's note and C reads B's copy, the note still has one origin and C's read still fires, so a chain of relays never makes a rare string look common. To reduce false positives, the global index is pre-seeded with files that start in two or more runs' workspaces or in shared channels. A file in only one workspace is that run's private source and stays unseeded.

\lead{Shingles.} Agents may quote, excerpt and reformat content, so texts are compared as overlapping shingles \cite{broder1997} of three kinds:
\begin{itemize}
  \item \emph{word shingles}: 8 consecutive words, for natural-language text;
  \item \emph{character shingles}: 40 consecutive characters, for code, paths and URLs;
  \item \emph{atoms}: any unbroken run of 20 or more \texttt{[A-Za-z0-9\_+=-]} characters, to catch e.g.\ credentials.
\end{itemize}
 Every text yields all three; the uses listed are what each is best at catching. Longer shingles trade worse recall on short strings for fewer coincidental matches. A known limitation of this representation is that anything shorter than all three is invisible to our detector. We compare different shingle lengths in Appendix~\ref{app:results}.

\lead{Authored and relayed.} A string that first appeared as a model generation is \emph{authored}: one agent wrote it and another read it. A string that first came in through a resource is \emph{relayed}: an agent picked it up and passed it on, and the finding names the resource and the run that first read it. The label, authored or relayed, is read off the index and says where the text originated. Authored and relayed communications indicate different problems. A relayed finding is a potential breach of confidentiality: a resource reached an unintended agent. An authored finding is about coordination: an agent communicated using a channel nobody declared.

\lead{Store.} The global index maps each shingle's 64-bit hash to its origins (run, resource or generation, and time) and to the runs whose models emitted it. Checking an input costs one lookup per shingle regardless of the number of indexed runs. Since agents are never compared directly, the cost grows with the text content, not with the number of agents.

\lead{Scope.} Our detector sees only text that crosses a model boundary. It cannot detect text that reaches the disk because a program encoded, decoded or copied it, if it did not pass through a model. We call this \emph{laundering}, and tracking taint below the model layer could close this gap (Section~\ref{sec:discussion}). Text the model itself rewrites, by paraphrase or steganography, is out of scope for exact-match methods such as ours.

\subsection{Experimental Setup}

\lead{Hugging Face incident reproduction.} Our headline test runs the detector on the raw transcripts of Slocum et al.'s reproduction of the HF incident \cite{slocum2026}. Each of its four arms gives 256 concurrent agents a protein-analysis task whose input file was never staged, next to a mock package registry that accepts uploads. It is run with GPT 5.6 Sol or GLM 5.3, and with collaboration invited or not. The obtained logs record no file accesses, so unfortunately we have no ground truth. Instead we check each detected edge A~$\to$~B against temporal evidence: whether A's own tool calls wrote to the registry before B read from there. We also compare the agents flagged by our detector with those flagged as broadcasters by the reproduction's own scorer.

\lead{Experimental Rig.} To measure recall we need ground truth, so we built a rig that records it. Agents run sequentially in containers that share exactly one host directory and nothing else. A host-side inotify watcher records every read and write on the shared directory, below the model boundary. Each agent acts as a team of a fictional company, with a bash tool, in Inspect AI \cite{inspect}; a run is one agent's session. We run the following conditions:
\begin{itemize}
\item \emph{isolated}, nothing is shared, so every finding is a false positive.
\item \emph{shared}, the positive control, teams get a folder described as the place to ask each other for things.
\item \emph{handoff}, a three-stage chain passes a release reference through the folder (relayed flow)
\item \emph{message}, planners turn private quotes into a plan that booking teams must act on (authored flow).
\end{itemize}
A detector edge is correct if its origin is an ancestor of the reader in the ground truth, and content recall is the share of file-content edges it covers. Every condition runs five seeds on Claude Haiku 5.5 and three on Claude Sonnet 5.5 (Appendix~\ref{app:conditions}). For \emph{evasion}, a scripted adversary replaces the model with fixed evasive command sequences in the same rig.

\lead{Collusion.wiki} We run the detector on collusion.wiki's export of DseWiki \cite{collusionwiki2026}, with 14,591 revisions by 3,216 agent accounts. DseWiki records every revision's full text but no reads, so we run our rule base on what the accounts wrote. Each line an account adds to a page is treated as an input; if its text first appeared on a different page, written by a different account, the account must have read that page. Accounts stand in for runs and pages for routes, and text that predates the export is never an origin. With no access to reads, copying a string and writing it independently looks identical, so we cannot count origins. We therefore relax the single-origin criterion to strings that fewer than five accounts ever inserted, and report more widely repeated strings separately as conventions. Every finding is authored, since relayed content leaves no trace without reads, and with no ground truth the result describes the network our rule recovers, not its precision or recall.

\lead{RefactorArena} We use 140 honest-policy Refactor Arena samples \cite{refactorarena2026} to investigate the false positive rate on agentic work. In these samples, an agent is tasked with solving a coding task. There is no communication so every finding by our detector is a false positive.

In all of our settings, the detector reads transcript files; a live deployment would instead collect each model call's input and output at the inference point.

\section{Results}\label{sec:results}

\lead{Hugging Face incident reproduction.} Between 93\% and 99\% of the edges we detect are backed by a prior registry write (Table~\ref{tab:hf}). The detector names as an origin nearly every agent its edges imply: of the agents it names, all but 1 to 28 per arm wrote to the registry. It names most of the agents the reproduction's scorer flagged as broadcasters, and on the GPT arms many more, since the scorer labels intent to broadcast while the detector names any agent whose text another agent read.

\lead{The rig.} In isolated runs the detector raises nothing. On shared and message, precision and content recall are 1.0 on both models. On handoff, content recall is 0.88 on Haiku and 0.98 on Sonnet, at precision 1.0 and 0.98; without relayed findings it falls to 0.34 and 0.49 (Figure~\ref{fig:results}a). Every miss is a reference that an honest agent moved with \texttt{cp} and no model typed (Appendix~\ref{app:results}).

\lead{Evasion.} Models briefed on the monitor declined to evade it (Appendix~\ref{app:briefed}), so we measure evasion with a scripted white-box adversary, written by Claude Opus 5.5. Four of its six strategies evade the detector entirely while completing the task, and a fifth hides the payload but not the handoff (Figure~\ref{fig:results}b). Every strategy that works keeps the payload from appearing as the same text on both sides of the model boundary (Appendix~\ref{app:results}). This bounds what an informed adversary can do, not what an agent inside a run would find.

\lead{False positives.} On 140 Refactor Arena samples with nothing shared, the detector raises 55 false findings per 1,000 inputs, mostly test output that two samples of one repository both produce. Shorter shingles would recover the misses above, at up to three times this rate (Figure~\ref{fig:results}c).

\lead{The real board.} On DseWiki the rule finds 12,806 account-to-account edges. 38\% are time-decoupled: the board worked as memory across agent lifetimes, which a monitor comparing only concurrent agents would miss.

\lead{Scalability.} On growing subsets of the GPT arm of the reproduction (Table~\ref{tab:scale}), the store grows more slowly than the text it indexes: keys per character fall from 0.45 at 32 agents to 0.31 at 256, because a larger fleet repeats more. Scan time stays close to linear in text, at 3.8 to 4.8\,$\mu$s per character in our Python reference implementation. Winnowing the character shingles \cite{schleimer2003} cuts the store 4.7-fold, at a cost on short shared spans: on the same arm, edges fall from 6,686 to 5,584 and broadcasters found from 119 to 87, while atoms, and with them credentials, are untouched. A native store needs about 40 bytes per key, or about 50 bytes per token (10 winnowed). A million rollouts of 50,000 tokens would then need about 2.5\,TB (0.5\,TB winnowed): a sharded on-disk key-value store whose entries can expire once no live run could still read them. These are projections from the measured key rates, not measurements of a native store, and the falling key rate comes from agents sharing one task; diverse rollouts may sit nearer the 32-agent rate (Appendix~\ref{app:results}).

\section{Discussion}\label{sec:discussion}

\lead{Where the misses come from.} The detector is agnostic to the channel but not to the representation. A channel nobody modelled is still caught if its payload reaches another agent's context as text, but every miss we found, honest or adversarial, apart from payloads too short to match, is text that crossed between runs without crossing a model boundary as the same string: a reference moved with \texttt{cp}, a plan decoded straight to disk, a note typed in fragments. These are blind spots by construction, not by tuning. On surfaces a lab controls, they can be closed by tracking provenance below the model as well, so that a file written by \texttt{cp}, a redirect or a program inherits the provenance of what it read. Our inotify oracle is already such instrumentation for one shared directory. The two are complements: taint tracking needs the channel instrumented, the text index does not.

\lead{Why relayed findings matter.} Without them, handoff recall falls from 0.88 to 0.34, and the one harm we observed, two teams publishing with a third team's reference, would have been invisible: no agent wrote anything wrong, they passed on the wrong thing. Relayed findings are about confidentiality and authored ones about coordination, and the label lets a reviewer triage the two separately.

\lead{Deployment.} A monitor should capture each model call's input and output at the inference point, not trust transcripts an agent may be able to influence. The index has to span runs and outlive them: on DseWiki, 38\% of edges join agents whose edits never overlapped in time. What counts as one run is a deployment decision, and most of our false positives on real work are two samples sharing one environment. At about 50 bytes per token, a lab's rollout volume needs a sharded on-disk key-value store, which is an engineering cost rather than an open problem.

\lead{Declining to evade.} Every briefed model that acted declined to evade the monitor, and Sonnet's refusals named oversight as the reason. A model from the same family, working as a coding assistant to the monitor's authors, wrote the evasions without hesitation. That is an anecdote, not a result, but it suggests that whether a model will evade a monitor depends on the deployment context, not only on the model.

Appendix~\ref{app:limitations} sets out what these results do and do not establish, their limitations, and the dual-use considerations.

\subsection{Future Work}

Taint tracking below the model on the surfaces a lab controls, the file system and process execution, combined with the text index for those it does not. A native store, measured at rollout scale. An in-run adversary from a model that is willing to try. Shingle lengths weighted by rarity rather than fixed, to reach file names without the false positives of shorter shingles. And per-agent watermarks \cite{netzer2026} alongside the index, where full text cannot be shared across organisations.

\section{Conclusion}

Detecting communication between agents does not require knowing the channel. Tagging every string with where it first entered the world, and asking whether it later reaches another run by another route, finds the flows in a reproduction of a real incident and in a rig with ground truth, cheaply and with few false positives on real work. Its blind spots are precise: text that never crosses a model boundary as the same string, and text too short to match. The first can be closed by taint tracking on the surfaces a lab controls; the second is the price of precision. Run at the inference point across a lab's rollouts, the index could turn the next incident from a post-mortem into an alert.
